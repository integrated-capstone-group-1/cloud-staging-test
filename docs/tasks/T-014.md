## 2. In-Scope Contract Slice
* **Zero-Trust Network Cloaking & Capabilities (Docker Compose - Resolving B-08):**
  * Microservices (`accounts-service`, `transaction-service`, `login-service`, `registration-service`, `risk-engine`, `forex-service`, `notification-service`, `reconciliation-service`), Oracle XE (`1521`), PostgreSQL (`5432`), Kafka (`9092`), and Redis (`6379`) reside strictly on internal bridge network `banking-net`.
  * **ONLY Port 8080** (API Gateway) and **Port 8090** (Admin Web) publish host ports (`ports: ["8080:8080"]`, `ports: ["8090:8090"]`).
  * Grafana runs internally on `:3000` accessible via reverse proxy or dev profile only.
  * Oracle container defines `cap_add: [NET_ADMIN]` so `tc qdisc` netem delay commands can execute cleanly without permission errors.
* **Observability Stack:**
  * Prometheus scrapes Actuator metrics.
  * Grafana provisions real-time dashboards for TPS, p95 latency, Hikari pool utilization, and Kafka lag.
* **Graded Chaos Engineering Test Automation (ADR-003):**
  1. *Scenario 1 (`CH-01`):* Oracle DB netem delay 800ms $\implies$ Resilience4j breaker trips to `OPEN`, balance queries return cached data with timestamp, mutations fail safe.
  2. *Scenario 2 (`CH-02`):* `docker stop risk-engine` $\implies$ Payment fails closed $\le 200\text{ms}$ with `503 SECURITY_CHECK_UNAVAILABLE`. Zero balance changes.
  3. *Scenario 3 (`CH-03`):* Network port scan against `:8081-8088`, `:1521`, `:5432` $\implies$ All refuse connection (`TcpTestSucceeded : False`).
  4. *Scenario 4 (`CH-04`):* `docker stop postgres-audit-db` $\implies$ Oracle payments succeed, Kafka audit consumer pauses and retries with backoff, audit parity reaches 100% on container restart.
