## 2. In-Scope Implementation Slice
* **Zero-Trust Network Cloaking (Docker Compose):**
  * All 7 internal microservices, Oracle XE (`1521`), PostgreSQL (`5432`), Kafka (`9092`), and Redis (`6379`) reside strictly on internal bridge network `banking-net`.
  * **ONLY Port 8080** (API Gateway) and **Port 8090** (Admin Web) publish host ports (`ports: ["8080:8080"]`).
* **Observability Stack:**
  * Prometheus scrapes `/actuator/prometheus` on Gateway and internal services.
  * Grafana dashboards provisioned on `:3000` tracking TPS, p95 latency, connection pool usage, and Kafka lag.
* **Chaos Engineering Automated Runbooks (from `docs/ACCEPTANCE.md`):**
  1. *Scenario 1:* `tc qdisc add dev eth0 root netem delay 800ms` on Oracle $\implies$ verifies Resilience4j breaker trips to `OPEN` and balance queries serve from Redis cache.
  2. *Scenario 2:* `docker stop risk-engine` $\implies$ verifies payments fail closed within $200\text{ms}$ with `SECURITY_CHECK_UNAVAILABLE`.
  3. *Scenario 3:* Network port scan on localhost `:8081-8087`, `:1521`, `:5432` $\implies$ verifies `TcpTestSucceeded : False`.
  4. *Scenario 4:* `docker stop postgres-audit-db` $\implies$ verifies customer payments succeed in Oracle, consumer retries, and audit parity restores 100% on container restart.

## 3. Strict Rules & Constraints
* Never expose database or messaging ports directly on developer host in production compose profile.
* Chaos scripts must leave no residual network delay or stopped containers after execution.
