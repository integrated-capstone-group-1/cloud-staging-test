## 3. In-Scope Implementation Slice
* **Home Screen:**
  * Displays Primary PHP Pocket balance and horizontal carousel for USD/EUR pockets.
  * Shows last 5 transactions and quick "Send Money" action button.
  * Degraded mode: displays last-known cached balance with clear timestamp label.
* **Virtual Card Hub:**
  * Displays 16-digit masked PAN (`4532-XXXX-XXXX-8821`), expiry, and toggle switch for live Card Lock/Unlock.
* **Send Money & Funding Options Sheet:**
  * Recipient input field with live recipient lookup showing masked name (e.g., "Maria S.").
  * Amount and currency selector.
  * If backend responds with `INSUFFICIENT_FUNDS` and `funding_options`:
    * Pops open the **Funding Options Bottom Sheet**.
    * Shows the exact shortfall, conversion rate, fee breakdown, and a 30-second live countdown timer.
    * Customer confirms funding pocket $\to$ calls `POST /api/v1/payments` with `funding_pocket_id` and `quote_id`.
* **Receipt Screen:**
  * Displays transaction reference ID (`FT2627800001`), payment amount, converted amount, fee, and timestamp.

---

## 4. Strict Rules & Constraints
* Customer must explicitly tap and confirm the funding pocket before any cross-currency payment is sent.
* Do not allow retries without reusing the same `X-Idempotency-Key` for the action.
