## 3. In-Scope Implementation Slice
* Dual DataSource Configuration:
  * Read-only connection to Oracle XE (`oracleDataSource`).
  * Read/Write connection to PostgreSQL (`postgresDataSource`).
* Scheduled Reconciliation Run:
  1. Creates row in PostgreSQL `recon_run_audit` with `run_status = 'RUNNING'`.
  2. Reads live `balance_amount` from Oracle `account_master` for each active account.
  3. Calculates expected balance from PostgreSQL:
     $$\text{Expected Balance} = \sum(\text{CREDIT legs}) - \sum(\text{DEBIT legs})$$
  4. Compares live balance with expected balance:
     * If matched: logs matched item.
     * If variance detected: inserts exception row into `recon_result_audit` (`recon_status = 'EXCEPTION'`, `exception_type = 'BALANCE_DRIFT'`, variance amount, severity).
     * Publishes high-priority `reconciliation.discrepancy` event to Kafka topic `audit.events`.
  5. Updates `recon_run_audit` status to `'COMPLETED'` with counts.

---

## 4. Strict Rules & Constraints
* Read-only access to Oracle XE: Never mutate balances from the reconciliation service.
* Runs in background without blocking customer transactions.
