## 2. In-Scope Contract Slice
* Expose public port `:8080`.
* Implement route mapping:
  * `/api/auth/**` -> `http://login-service:8082` & `http://registration-service:8081` (Public)
  * `/api/v1/payments/**`, `/api/v1/cards/**` -> `http://transaction-service:8084` (Authenticated)
  * `/api/v1/accounts/**` -> `http://accounts-service:8083` (Authenticated)
  * `/api/v1/fx/**` -> `http://forex-service:8087` (Authenticated)
* Filter Chain:
  1. Strip untrusted client headers: remove any incoming `X-Cust-Id` or `X-Cust-Role`.
  2. Rate Limiting: Redis token-bucket filter (replenish rate: 15/s, burst: 30/s per IP/User). If exceeded, return `HTTP 429 Too Many Requests`.
  3. JWT Authentication: Verify HMAC-SHA256 signature and expiration.
  4. Check Redis blacklist (`token:<jwt_hash>`). If blacklisted, return `HTTP 401 Unauthorized`.
  5. Decorate forwarded request with verified headers: `X-Cust-Id` and `X-Cust-Email`.

---

## 3. Strict Rules & Constraints
* Fail-Closed Security: If Redis is down during the token blacklist check, fail closed (`HTTP 401`).
* Rate Limiting Fail-Open: If Redis is down during rate limiting check, log a warning and allow the request.

## 4. Done-When Command

./mvnw test -pl api-gateway -Dtest=GatewayRoutingAndSecurityTest

Test suite must pass verifying:
1. Public login route forwards without JWT.
2. Protected `/api/v1/payments` route rejects unauthenticated request with 401.
3. Blacklisted token returns 401.
4. Request flood triggers HTTP 429.
