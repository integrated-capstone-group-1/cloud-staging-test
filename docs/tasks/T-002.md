---

## 3. Strict Rules & Constraints
* **Deadlock Prevention:** Sort all `account_id` strings in ascending alphanumeric order before querying.
* Execute a single locking query:
  ```sql
  SELECT balance_amount FROM account_master WHERE account_id IN (...) ORDER BY account_id FOR UPDATE
  ```
* Enforce account status check: reject any mutation on an account where `account_status != 'ACTIVE'`.
* Enforce non-negative balance: check `balance_amount - debit_amount >= 0` before mutating.
* In the **exact same Oracle local `@Transactional` commit**:
  1. Update `balance_amount` across all accounts.
  2. Insert an event into `outbox_master` with `aggregate_type='TRANSACTION'`, `event_type='payment.completed'`, and full leg payload.
* Invalidate Redis `balance_cache:{accountId}` post-commit.

## 4. Done-When Command
```bash
./mvnw test -pl accounts-service -Dtest=CoreSettlementServiceTest
```
Test suite must pass verifying:
1. 4-leg transaction mutates all balances correctly in a single transaction.
2. Concurrent reverse-order requests (A->B while B->A) complete without SQL deadlocks.
3. Insufficient balance rolls back completely and writes zero outbox rows.
