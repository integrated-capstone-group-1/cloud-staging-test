## 3. In-Scope Implementation Slice
* Background Scheduler running nightly `@Scheduled(cron = "0 0 0 * * *")` (or triggered on-demand via Admin API `POST /api/v1/admin/batch/eod`):
* **Standing Instruction Processing:**
  1. Queries Oracle `standing_instruction` where `status = 'ACTIVE'` and `next_execution_date <= CURRENT_DATE`.
  2. For each instruction:
     * Generates a deterministic idempotency key: `SI-{instructionId}-{executionDate}`.
     * Invokes `PaymentOrchestrator` to execute the payment between source and target accounts.
     * Advances `next_execution_date` according to `frequency` (DAILY, WEEKLY, MONTHLY).
* **EOD Completion & Audit:**
  * Publishes `batch.eod.completed` event to Kafka topic `transaction.events`.

---

## 4. Strict Rules & Constraints
* Fail-Safe Execution: If one standing instruction fails (e.g. source account has insufficient funds), log the failure, skip to the next instruction, and do not crash the batch job.
* Idempotency Guard: Running the EOD job twice on the same day must not double-execute standing instructions.
