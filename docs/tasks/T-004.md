## 2. In-Scope Contract Slice
* Relay polls Oracle `outbox_master` where `status = 'PENDING'` every 500ms, publishes to Kafka topic `transaction.events`, and updates `status = 'PUBLISHED'`.
* `AuditLedgerConsumer` listens to `transaction.events`:
  * Parses leg items from `payment.completed` event schema specified in [`docs/CONTRACTS.md`](file:///c:/Users/RBS83790/OneDrive%20-%20EastWest%20Banking%20Corporation/Documents/training/integrated-capstone/capstone-banking-system/docs/CONTRACTS.md#L240-L290).
  * **Deterministic UUID Generation (Resolving B-04):**
    For each leg, generates deterministic UUIDv5:
    $$\text{mutation\_uuid} = \text{UUIDv5}(\text{Namespace}, \; \text{txn\_id} + \text{"-leg-"} + \text{leg\_no})$$
  * Inserts row into PostgreSQL `ledger_mutation_audit` with `(mutation_uuid, txn_id, account_id, leg_no, amount, currency, mutation_type, audit_state='COMMITTED')`.
  * If a redelivered Kafka message is processed, PostgreSQL enforces `UNIQUE (txn_id, leg_no)`, safely ignoring duplicate insertion without error.

---

## 3. Strict Rules & Constraints (Do Not Touch)
* **Immutability Protection:** Never issue `UPDATE` or `DELETE` on `ledger_mutation_audit`. Database triggers will block and throw an exception.
* **Resilience During Postgres Outages:**
  * If PostgreSQL is unreachable, `AuditLedgerConsumer` must **pause container consumption and retry with backoff**.
  * **DO NOT** route transient database connection errors to `.DLT` or `*.dlq`. Only corrupted, unparseable poison messages go to `.dlq`.
