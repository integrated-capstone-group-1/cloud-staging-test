# Task T-004: Asynchronous Outbox Relay & Audit Ledger Consumer

**Goal:** Implement the reliable Kafka event publishing pipeline from Oracle `outbox_master` and the idempotent consumer appending rows to PostgreSQL `ledger_mutation_audit`.

**Requirement IDs:** BR-02, TR-L03, TR-L04, TR-L05, TR-L07

---

## 1. Files in Scope
* `accounts-service/src/main/java/com/bank/accounts/service/OutboxMasterRelayService.java`
* `transaction-service/src/main/java/com/bank/transaction/consumer/AuditLedgerConsumer.java`
* `transaction-service/src/main/java/com/bank/transaction/repository/LedgerMutationAuditRepository.java`

---

## 2. In-Scope Contract Slice
* Relay polls Oracle `outbox_master` where `status = 'PENDING'` every 500ms, publishes to Kafka topic `transaction.events`, and updates `status = 'PUBLISHED'`.
* `AuditLedgerConsumer` listens to `transaction.events`:
  * Parses leg items from `payment.completed`.
  * For each leg, generates a `mutation_uuid` and inserts a row into PostgreSQL `ledger_mutation_audit`.
  * Sets `audit_state = 'COMMITTED'`.

---

## 3. Strict Rules & Constraints
* **Immutability Protection:** Never issue `UPDATE` or `DELETE` on `ledger_mutation_audit`. Database triggers will block and throw an exception.
* **Resilience During Postgres Outages (Resolving B-07):**
  * If PostgreSQL is unreachable, `AuditLedgerConsumer` must **pause container consumption and retry with backoff**.
  * **DO NOT** route transient database connection errors to `.DLT` (Dead Letter Topic). Only corrupted, unparseable poison messages go to `.DLT`.

---

## 4. Done-When Command
```bash
./mvnw test -pl transaction-service -Dtest=AuditLedgerConsumerTest
```
Test suite must pass verifying:
1. `payment.completed` event generates corresponding DEBIT and CREDIT rows in PostgreSQL.
2. Simulated PostgreSQL transient exception causes retry without data loss.
3. Reprocessed identical event does not produce duplicate balance drifts.
