Status: VERIFIED

## Breaker section
Severity:         S1
Oracle:           F3, F6, F7, F8
Domain / journey: identity-admin, perimeter / admin ops
Attack area:      Area 6 (Business logic & Network Boundary Protection)
Reproducibility:  3 of 3 attempts (100%)
Reproduction:
```bash
# 1. Authenticate via Gateway as customer
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan.delacruz@example.com","password":"password123"}'
# Extract Bearer token <jwt>

# 2. Invoke legacy ledger mutate directly through Gateway

    "accountId": "3722f77f-3d1b-4d55-8f83-b71bac91d095",
    "amount": "10.0000",

    "txnType": "DEPOSIT",
    "idempotencyKey": "45d19e68-0000-4000-8000-000000000099"
  }'
```

## Fixer section (fixer only)
- **Status:** VERIFIED
- **Classification:** `CODE_BUG`
- **Owner:** Russel (`api-gateway`), Rohan (`transaction-service`), Yancey (`accounts-service`)
- **Root cause:** 
  1. In `api-gateway`: `GatewayRouteIsolationFilter` defines `MUTATION_ROUTE_PATTERN = Pattern.compile("^/api/accounts/(?:[^/]+/)?(credit|debit)(?:/.*)?$")` and checks `/internal/**`, but does not match `/api/v1/ledger/mutate` or `/api/v1/accounts/*/credit` / `/api/v1/accounts/*/debit`.
  2. Because `GatewayRouteIsolationFilter` runs before route filters, unblocked paths proceed to route filters where `/api/v1/ledger/**` is protected only by `JwtAuthentication`. Authenticated customers are permitted to invoke `/api/v1/ledger/mutate` directly through the edge gateway.
  3. Furthermore, in `transaction-service`, `SecurityConfig` allows `hasAnyRole("CUSTOMER", "ADMIN", "INTERNAL")` on `/api/v1/ledger/**`, and `accounts-service` allows `hasAnyRole("CUSTOMER", "ADMIN", "INTERNAL")` on `/api/v1/accounts/**`.
- **Files affected:**
  - `api-gateway/src/main/java/com/capstone/gateway/filter/GatewayRouteIsolationFilter.java`
  - `api-gateway/src/test/java/com/capstone/gateway/filter/GatewayRouteIsolationFilterTest.java`
  - `api-gateway/src/test/java/com/capstone/gateway/GatewayPerimeterSecurityIntegrationTest.java`
- **Sibling check:**
  - `/api/v1/accounts/{id}/credit` and `/api/v1/accounts/{id}/debit` (missed by `/api/accounts/` pattern without `v1`).
  - `/api/accounts/credit` and `/api/accounts/debit` (already covered by existing regex).
  - `/internal/**` (already covered by prefix check).
  - Updating pattern to: `^/api(?:/v1)?/accounts/(?:[^/]+/)?(credit|debit)(?:/.*)?$` and explicitly checking `/api/v1/ledger/mutate`.
- **Contract / invariant enforced:**
  - `docs/CONTRACTS.md` line 17: "Network Boundary Protection (B-06): Core settlement (/internal/core/settlement/**), account direct balance mutations (/api/accounts/*/credit, /api/accounts/*/debit, /api/v1/accounts/*/credit, /api/v1/accounts/*/debit), and risk internal routes (/internal/risk/**), and the legacy ledger adapter (/api/v1/ledger/mutate) are strictly blocked at the API Gateway with 403 Forbidden."
  - Invariants I-9 (Baseline S drift) and I-10 (account balance equals ledger entry sum).
- **Contradiction check:**
  - In `frontend-web`, `HttpBankingApiClient` calls `/api/v1/ledger/mutate` directly via Gateway for transaction execution forms. If blocked at the Gateway with 403 Forbidden, `frontend-web` customer transactions that use this legacy route will fail with 403 unless routed via internal microservice network or redirected to `/api/v1/payments`. However, CONTRACTS.md line 17 explicitly mandates that `/api/v1/ledger/mutate` is strictly blocked at the API Gateway with `403 Forbidden` (`B-06`).
  - In `docs/FIXER.md`, `DO_NOT_TOUCH` includes `api-gateway (in progress)` unless a finding is approved.
- **Schema or migration impact:**
  - None. No database schema or migration changes required.
