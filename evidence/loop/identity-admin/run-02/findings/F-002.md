# F-002 HTTP 500 Internal Server Error and Java class leak on payment with funding_pocket_id
Status: VERIFIED

## Breaker section
Severity:         S2
Oracle:           F1, F2
Domain / journey: identity-admin, E2E-02 / E2E-03 (payments & smart routing)
Attack area:      Area 1 (Input) & Area 5 (FX and shortfall)
Reproducibility:  3 of 3 attempts (100%)
Reproduction:
```bash
# 1. Authenticate as customer
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan.delacruz@example.com","password":"password123"}'
# Extract Bearer token <jwt>

# 2. Submit payment specifying a funding_pocket_id without a quote_id
curl -s -X POST http://localhost:8080/api/v1/payments \
  -H "Authorization: Bearer <jwt>" \
  -H "X-Idempotency-Key: $(uuidgen)" \
  -d '{
    "recipient_account_id": "f95e7e52-3259-4b4d-ac66-b186a893cf66",
    "amount": "100.0000",
    "currency": "PHP",
    "funding_pocket_id": "a86c97cc-1ea5-4767-bd5b-148968354f9c"
  }'
```
Expected:         docs/CONTRACTS.md line 23 & line 166: Missing required fields or invalid shortfall configuration must return HTTP 400 Bad Request with error code VALIDATION_FAILED or QUOTE_EXPIRED. It must never throw an unhandled 500 or leak internal class names.
Actual:           HTTP 500 Internal Server Error returned:
```json
{
  "type": "https://capstone.bank/errors/internal",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "An unexpected error occurred: Cannot invoke \"com.capstone.orchestrator.dto.PaymentResponse.getStatus()\" because \"response\" is null",
  "instance": "/api/v1/payments",
  "timestamp": "2026-10-09T11:27:56.697599211Z"
}
```
Leaks internal implementation class `com.capstone.orchestrator.dto.PaymentResponse` in the `detail` property.
Invariant output: Invariant check clean (exit code 0; no DB corruption occurred).
Observed scope:   Any payment invocation specifying `funding_pocket_id` without `quote_id` crashes the orchestrator service with NullPointerException instead of returning RFC 7807 validation error.

## Fixer section (fixer only)

### Step E Proposal
- **Classification:** CODE_BUG
- **Owner:** Rohan (`orchestrator-service`), Common (`common`)
- **Root Cause:**
  1. `PaymentForwardingController.java` omits verification of `funding_pocket_id` ownership (violating `CONTRACTS.md` line 166) and does not validate that `quote_id` is supplied when a shortfall `funding_pocket_id` is specified.
  2. `TransactionClient.java` only handles HTTP status codes 409, 422, 404, 503 in `defaultStatusHandler`. Status codes 400 or 500 fall through without throwing an exception, causing RestClient to return `null` for `body(PaymentResponse.class)`.
  3. `PaymentForwardingController.java` invokes `response.getStatus()` without checking for `null`, generating a `NullPointerException`.
  4. `GlobalExceptionHandler.java` concatenates raw `ex.getMessage()` into the 500 `detail` field (`"An unexpected error occurred: " + ex.getMessage()`), leaking internal Java class names (`com.capstone.orchestrator.dto.PaymentResponse`).
- **Files Affected:**
  - `orchestrator-service/src/main/java/com/capstone/orchestrator/controller/PaymentForwardingController.java`
  - `orchestrator-service/src/main/java/com/capstone/orchestrator/client/TransactionClient.java`
  - `common/src/main/java/com/capstone/common/exception/GlobalExceptionHandler.java`
- **Diff Summary (Proposed, not applied):**
  - `PaymentForwardingController.java`:
    - Validate that if `fundingPocketId` is present, `quoteId` must not be null/blank (`IllegalArgumentException("quote_id is required when funding_pocket_id is specified")`).
    - Invoke `ownershipService.verifyAccountOwnership(request.getFundingPocketId(), "funding pocket payment")`.
    - Add null check on `response` before inspecting status.
  - `TransactionClient.java`:
    - Add handler for status 400 (throw `IllegalArgumentException`).
    - Add fallback `else` branch for unhandled error statuses (throw `IllegalStateException`).
  - `GlobalExceptionHandler.java`:
    - In `handleIllegalArgument`: set `error_code` property to `VALIDATION_FAILED`.
    - In `handleGeneric`: sanitize `detail` to `"An unexpected error occurred"` without leaking raw exception message/class names.
- **Contract Line / Invariant Enforced:**
  - `docs/CONTRACTS.md` line 23: `400 Bad Request | VALIDATION_FAILED`
  - `docs/CONTRACTS.md` line 166: `funding_pocket_id must belong to the caller; quote_id must belong to the caller, match the shortfall and be unexpired (400 QUOTE_EXPIRED).`
  - RFC 7807 sanitization: no internal class or stack leaks.
- **Contradiction Check:**
  - Normal payments without shortfall (`funding_pocket_id == null`) are completely untouched.
  - Legitimate shortfall payments provide both `funding_pocket_id` and `quote_id`, and will continue to pass normally.
  - Sibling check: checked other `defaultStatusHandler` implementations in `CoreBankingClient` (already handles 400 and default `else`), `HttpAccountsServiceClient`, and `AccountsClient`.
- **Schema / Migration Impact:** None.
- **Regression Test:**
  - JUnit in `PaymentForwardingControllerTest.java`: test rejection when `funding_pocket_id` provided without `quote_id`, and verify `verifyAccountOwnership` is called for `funding_pocket_id`.
  - Integration test in `ChannelOrchestratorIntegrationTest.java`: assert 400 `VALIDATION_FAILED` response.
  - Blackbox curl replay of F-002 reproduction command.
- **Commands to run:**
  - `mvn test -pl common`
  - `mvn test -pl orchestrator-service`
  - `python tests/invariants/check_invariants.py --scope global --wait-drain 30`
- **Regression Risk:** Low. Additive boundary validation and exception sanitization only.
