# F-006 HTTP 500 Internal Server Error and Gateway crash on client-supplied X-Cust-Id header
Status: VERIFIED

## Breaker section
Severity:         S2
Oracle:           F1, F4
Domain / journey: perimeter-ingress, E2E-09
Attack area:      Area 3 (Authorization & Header Sanitization)
Reproducibility:  3 of 3 attempts (100%)
Reproduction:
```bash
# 1. Authenticate as customer
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan.delacruz@example.com","password":"password123"}'
# Extract Bearer token <jwt>

# 2. Invoke any protected endpoint while supplying X-Cust-Id in request header
curl -s -X GET http://localhost:8080/api/v1/payments/history \
  -H "Authorization: Bearer <jwt>" \
  -H "X-Cust-Id: cust-admin-001"
```
Expected:         docs/CONTRACTS.md line 14 & docs/E2E_TEST_PLAN.md line 287 (E2E-09): Caller identity comes only from verified JWT; Gateway strips any client-supplied X-Cust-Id header and injects the verified token ID. Requests must process normally for the authenticated user and must never return HTTP 500 or break the RFC 7807 error format.
Actual:           Gateway crashes with HTTP 500 Internal Server Error, returning Spring Cloud Gateway's default non-RFC-7807 envelope:
```json
{
  "timestamp": "2026-10-10T03:42:24.545+00:00",
  "path": "/api/v1/payments/history",
  "status": 500,
  "error": "Internal Server Error",
  "requestId": "23a8fb2f-426"
}
```
Invariant output: Global invariant check passed (exit 0); request failed before reaching service logic or mutating state.
Observed scope:   Affects all Gateway-protected endpoints (`/api/v1/payments/history`, `/api/v1/accounts/{id}/pockets`, `/api/v1/cards`) whenever a caller passes `X-Cust-Id`.

## Fixer section (fixer only)

### Step E Proposal
- **Classification:** CODE_BUG
- **Owner:** Russel (`api-gateway`)
- **Root Cause:**
  In `SecurityHeadersFilter.java`, `request.mutate().headers(httpHeaders -> httpHeaders.remove(headerName))` attempted in-place modification on incoming request headers. In Spring WebFlux with Reactor Netty at runtime, incoming request headers are wrapped in `ReadOnlyHttpHeaders`, which throws `java.lang.UnsupportedOperationException` whenever `.remove()` is called, crashing the Gateway filter chain with HTTP 500.
- **Files Affected:**
  - `api-gateway/src/main/java/com/capstone/gateway/filter/SecurityHeadersFilter.java`
- **Diff Summary:**
  Wrap the incoming `ServerHttpRequest` with `ServerHttpRequestDecorator` that copies headers into a fresh mutable `HttpHeaders` in `getHeaders()`, removes `UNTRUSTED_HEADERS`, and returns the sanitized headers without mutating `ReadOnlyHttpHeaders`. For unit test harness compatibility with `MockServerHttpRequest`, attempt builder mutation inside a try-catch ignoring `UnsupportedOperationException`.
- **Contract Line / Invariant Enforced:**
  - `docs/CONTRACTS.md` line 14: `Identity Propagation: Caller identity comes only from the verified JWT (the gateway injects X-Cust-Id after stripping any client-supplied value).`
  - `docs/E2E_TEST_PLAN.md` line 287 (E2E-09): `Step 3: Test header sanitization: Send request with valid token and forged header X-Cust-Id: cust-admin-001. Step 4: Assert response contains authenticated customer's pockets only, never admin's (identity comes from verified token).`
- **Contradiction Check:**
  - Clean requests with no spoofed headers continue to pass unchanged.
  - Downstream `JwtAuthenticationGatewayFilterFactory` decorates the request with verified JWT claims (`X-Cust-Id`, `X-Cust-Email`).
  - Unit tests (`SecurityHeadersFilterTest`, `HeaderSanitizationAndCorsTest`) continue to pass.
- **Schema / Migration Impact:** None.
- **Regression Risk:** None. Eliminates the runtime `UnsupportedOperationException` crash and enforces edge header sanitization.
