# F-008 Cross-customer FX quote hijacking permitted on POST /api/v1/fx/convert
Status: VERIFIED

## Breaker section
Severity:         S1
Oracle:           F7
Domain / journey: cross-domain
Attack area:      Area 3 (Authorization & IDOR)
Reproducibility:  3 of 3 attempts (100%)
Reproduction:
```bash
# 1. Authenticate as Customer A (Juan) and request an FX quote
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"juan.delacruz@example.com","password":"password123"}'
# Extract <juan_jwt>

curl -s -X GET "http://localhost:8080/api/v1/fx/quote?from=PHP&to=EUR&amount=10.0000" \
  -H "Authorization: Bearer <juan_jwt>"
# Extract quote_id e.g. "q-61393291-5249-44ff-9279-d840c85efa05"

# 2. Authenticate as Customer B (Maria)
curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"maria.santos@example.com","password":"password123"}'
# Extract <maria_jwt>

# 3. Customer B executes currency conversion consuming Customer A's quote_id
curl -s -X POST http://localhost:8080/api/v1/fx/convert \
  -H "Authorization: Bearer <maria_jwt>" \
  -H "Content-Type: application/json" \
  -d '{
    "quote_id": "q-61393291-5249-44ff-9279-d840c85efa05",
    "source_pocket_id": "f95e7e52-3259-4b4d-ac66-b186a893cf66",
    "target_pocket_id": "f95e7e52-3259-4b4d-ac66-b186a893cf66"
  }'
```
Expected:         docs/CONTRACTS.md Section 2.1 line 166: `quote_id must belong to the caller`. Cross-customer quote usage must be rejected with HTTP 403 Forbidden (`ACCESS_DENIED`) or 400 Bad Request. Per Security Override P-01 and Oracle F7, unauthorized cross-customer resource sharing/hijacking returning 2xx is an S1 security violation.
Actual:           HTTP 200 OK returned to Customer B; conversion is executed successfully using Customer A's quote:
```json
{
  "conversion_id": "conv-e0209bc7-fa31-4cdd-aaae-b4d95cb65e26",
  "quote_id": "q-61393291-5249-44ff-9279-d840c85efa05",
  "status": "COMPLETED",
  "source_pocket_id": "f95e7e52-3259-4b4d-ac66-b186a893cf66",
  "target_pocket_id": "f95e7e52-3259-4b4d-ac66-b186a893cf66",
  "source_amount_debited": 641.9875,
  "target_amount_credited": 10.0,
  "created_at": "2026-10-10T04:43:09.885775034Z"
}
```
Invariant output: Global invariant check passed (exit 0); balance conserved within Maria's pocket.
Observed scope:   Affects `POST /api/v1/fx/convert` when passing another customer's unexpired `quote_id`.

## Fixer section (fixer only)

### Step E Proposal
- **Classification:** CODE_BUG
- **Owner:** Rohan (`forex-service`) & Russel (`api-gateway`)
- **Root Cause:**
  1. `api-gateway` routes in `application.yml` and `application-docker.yml` routed `/api/v1/fx/**` without the `JwtAuthentication` gateway filter. Inbound requests were not forced through JWT validation at the edge and customer identity was not properly forwarded downstream.
  2. `forex-service` lacked `JwtAuthenticationFilter` in its `SecurityConfig` and omitted `com.capstone.common` in its component scan (`ForexServiceApplication`), leaving `SecurityContextHolder` unpopulated and `GlobalExceptionHandler` unloaded.
  3. `ForexQuoteService.generateQuote` generated quotes without capturing the calling customer's identity (`customerId`).
  4. `ForexQuoteService.convert` allowed any caller holding a valid `quote_id` to consume the quote regardless of whether the caller generated or owns the quote, violating `docs/CONTRACTS.md Section 2.1 line 166: quote_id must belong to the caller`.
- **Files Affected:**
  - `api-gateway/src/main/resources/application.yml`
  - `api-gateway/src/main/resources/application-docker.yml`
  - `forex-service/src/main/java/com/capstone/forex/ForexServiceApplication.java`
  - `forex-service/src/main/java/com/capstone/forex/config/SecurityConfig.java`
  - `forex-service/src/main/java/com/capstone/forex/dto/FxQuoteResponse.java`
  - `forex-service/src/main/java/com/capstone/forex/service/ForexQuoteService.java`
  - `forex-service/src/test/java/com/capstone/forex/ForexQuoteAndSchedulerTest.java`
- **Diff Summary:**
  1. `api-gateway`: Split `forex-service` route into public (`/api/v1/fx-rate/**`, `/api/v1/forex/**`) and secured (`/api/v1/fx/**`) with `JwtAuthentication` filter per `docs/FULL_SYSTEM_WIRING_GUIDE.md`.
  2. `forex-service`:
     - Added `scanBasePackages = {"com.capstone.forex", "com.capstone.common"}` to `ForexServiceApplication`.
     - In `SecurityConfig`, registered `JwtAuthenticationFilter` and secured `/api/v1/fx/**` requiring authenticated roles (`CUSTOMER`, `ADMIN`, `INTERNAL`).
     - In `FxQuoteResponse`, added `@JsonProperty("customer_id") private String customerId`.
     - In `ForexQuoteService.generateQuote`, captured `SecurityUtils.getCurrentCustomerId()` and attached it to the generated quote.
     - In `ForexQuoteService.convert`, enforced quote ownership via `SecurityUtils.checkCustomerAccess(quote.getCustomerId(), "execute FX conversion with quote " + quote.getQuoteId())`. Cross-customer attempts throw `AccessDeniedException`, mapped by `GlobalExceptionHandler` to `HTTP 403 Forbidden` (`ACCESS_DENIED`, RFC 7807 problem detail).
